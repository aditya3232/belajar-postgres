# Hal Unik dari PostgreSQL
### 1. Schema
- PostgreSQL memiliki *schema* sebagai namespace dalam satu database
- Memungkinkan tabel dengan nama sama selama berada di schema berbeda
- MySQL tidak memiliki konsep ini (schema = database)

### 2. CHECK Constraint
- PostgreSQL: fully supported dan konsisten
- MySQL 8+: support, tapi versi lama diabaikan
- PostgreSQL lebih strict dan reliable

### 3. Auto Number (Sequence, Serial & Identity)

- PostgreSQL:
  - Sequence:
    - Object terpisah (CREATE SEQUENCE)
    - Bisa reusable & configurable
  - Serial:
    - Shortcut untuk auto increment
    - Di belakang layar = INTEGER + DEFAULT nextval(sequence)
    - Contoh:
      ```sql
      id SERIAL
      ```
    - Kekurangan:
      - Kurang fleksibel dibanding sequence langsung
      - Dianggap "legacy" (masih banyak dipakai, tapi mulai digantikan Identity)
  - Identity:
    - Standar SQL modern (recommended)
    - GENERATED ALWAYS → tidak bisa override
    - GENERATED BY DEFAULT → bisa override
    - Contoh:
      ```sql
      id INT GENERATED ALWAYS AS IDENTITY
      ```

- MySQL:
  - Hanya AUTO_INCREMENT
  - Tidak ada sequence object

### 4. Operator Concatenation (||)
- PostgreSQL: `||` untuk string concat
- MySQL:
  - Default: `||` = OR
  - Bisa jadi concat jika mode `PIPES_AS_CONCAT` aktif
- Keduanya punya `CONCAT()`

### 5. DISTINCT ON
- PostgreSQL only
- Mengambil 1 baris pertama dari tiap group
- MySQL: pakai `ROW_NUMBER()` + subquery

### 6. CURRENT_DATE / CURRENT_TIMESTAMP
- PostgreSQL: `CURRENT_DATE`, `CURRENT_TIMESTAMP`
- MySQL: ada juga (`CURDATE()`, dll)
- Perbedaan hanya gaya penulisan

### 7. GROUPING SETS
- PostgreSQL: support multi-level grouping
- MySQL: hanya `ROLLUP`
- Cocok untuk laporan kompleks

### 8. RETURNING (DML)
- PostgreSQL: fully supported (INSERT, UPDATE, DELETE)
- MySQL 8.0.21+: ada, tapi lebih terbatas
- PostgreSQL lebih fleksibel

### 9. Strictness
- PostgreSQL lebih strict dalam constraint & tipe data

### 10. Placeholder Parameter
- PostgreSQL: `$1, $2, ...`
- MySQL: `?` (prepared statement)

### 11. Parameter Handling
- PostgreSQL: langsung positional parameter
- MySQL: sering pakai `@variable`

# Relasional vs Non-Relasional
### 1. Non-Relasional (NoSQL)
- Cenderung memiliki redundansi data
- Contoh:
  - MongoDB (JSON)
  - Redis (key-value)

### 2. Relasional (SQL)
- Mengurangi redundansi dengan relasi antar tabel
- Menggunakan normalisasi

### Normalisasi
- 1NF → 1 kolom = 1 nilai (tidak boleh array dalam kolom)
- 2NF → semua kolom bergantung ke seluruh primary key
  ❌ (order_id, product_id, product_name)
  ✅ product_name harus di tabel produk
- 3NF → tidak ada ketergantungan transitif (non-key ke non-key)

# SQL vs NoSQL
### Gunakan SQL jika:
- Struktur data jelas & tetap
- Butuh relasi antar data
- Butuh konsistensi tinggi (ACID)
- Query kompleks (JOIN, transaksi)

### Gunakan NoSQL jika:
- Struktur data fleksibel
- Traffic besar (high scalability)
- Tidak butuh relasi kompleks
- Contoh:
  - Logging system
  - Cache

# ACID (Transaction Concept)
ACID adalah prinsip utama transaksi database untuk menjaga konsistensi data.

### 1. Atomicity (All or Nothing)
- Semua query sukses → COMMIT
- Salah satu gagal → ROLLBACK

### 2. Consistency
- Data tetap valid sesuai constraint
- Contoh:
  - Tidak boleh melanggar FK
  - Tidak boleh data invalid

### 3. Isolation
- Transaksi tidak saling mengganggu
- PostgreSQL menggunakan MVCC
- Isolation level:
  - Read Committed (default)
  - Repeatable Read
  - Serializable

### 4. Durability
- Data yang sudah COMMIT tetap aman walau crash
- PostgreSQL menggunakan WAL (Write-Ahead Logging)
