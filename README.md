## Hal Unik dari PostgreSQL
```zsh
1. schemas
-> PostgreSQL punya schema sebagai namespace dalam 1 database
-> memungkinkan tabel dengan nama sama selama beda schema
-> MySQL tidak punya konsep ini (schema = database)

2. check constraint
-> PostgreSQL: fully supported dan konsisten untuk validasi data
-> MySQL 8+: sudah support CHECK, tapi versi lama diabaikan
-> PostgreSQL lebih strict dan reliable

3. autonumber (sequence & identity)
-> PostgreSQL:
   - sequence: object terpisah, bisa dipakai ulang & custom (start, increment, dll)
   - identity:
     * GENERATED ALWAYS (tidak bisa override)
     * GENERATED BY DEFAULT (bisa override, mirip auto_increment)
-> MySQL:
   - hanya AUTO_INCREMENT
   - tidak ada sequence object

4. operator concatenation (||)
-> PostgreSQL: || digunakan untuk menggabungkan string
-> MySQL:
   - default: || dianggap sebagai OR
   - bisa jadi concat jika mode PIPES_AS_CONCAT aktif
-> kedua DB juga punya function CONCAT()

5. DISTINCT ON (x)
-> PostgreSQL only
-> digunakan untuk mengambil 1 baris pertama dari setiap group
-> MySQL tidak punya, biasanya diganti dengan ROW_NUMBER() + subquery

6. current_date / current_timestamp
-> PostgreSQL: CURRENT_DATE, CURRENT_TIMESTAMP
-> MySQL juga punya fungsi yang sama
-> hanya beda gaya penulisan (misal CURDATE() di MySQL)

7. GROUPING SETS
-> PostgreSQL: support GROUPING SETS untuk multi-level grouping dalam 1 query
-> MySQL: tidak support GROUPING SETS (hanya ROLLUP)
-> berguna untuk laporan kompleks dalam 1 query

8. RETURNING (INSERT, UPDATE, DELETE)
-> PostgreSQL: mendukung RETURNING untuk mengambil data hasil DML
-> MySQL 8.0.21+: sudah support RETURNING (terbatas dibanding PostgreSQL)
-> PostgreSQL lebih fleksibel dan lebih dulu menyediakan fitur ini

9. PostgreSQL Lebih strict dalam constraint & tipe data
```

## sql & nosql
```zsh
1. bentuk data nosql -> bisa json (mongoDB), dan key-value (redis) 
2. kapan pakai sql -> struktur data fix tidak berubah, butuh proses berurutan dan konsisten (ACID), data punya relasi jelas
3. kapan pakai nosql -> struktur data fleksibel misal data user bisa memiliki field beda-beda, traffic besar dan tidak butuh relasi, misal log system, cache
```

## data type PostgreSQL
```zsh
1. numeric -> 
   smallint, integer, bigint, decimal, numeric, real, double precision, 
   serial ❌, bigserial ❌

2. date time -> 
   date, time, timestamp, 
   timestamptz ❌, interval ❌

3. boolean -> 
   boolean ❌ (di mysql = tinyint)

4. character -> 
   character, character varying, text, uuid ❌

5. json types -> 
   json, jsonb ❌

6. array -> 
   integer[], text[], dll ❌

7. xml type -> 
   xml ❌

8. binary data -> 
   bytea (mysql = blob)

9. enum -> 
   enum (ada di mysql, tapi beda implementasi)

10. network -> 
    inet ❌, cidr ❌, macaddr ❌

11. range types -> 
    int4range ❌, int8range ❌, numrange ❌, 
    tsrange ❌, tstzrange ❌, daterange ❌

12. composite type -> 
    custom type (row type) ❌

13. domain ->

    oid ❌

postgres unggul di:
- jsonb
```
